```sh
npx @eoria/cli add sheet
```

Needs `@gorhom/bottom-sheet`, which the CLI installs. It runs on Reanimated and Gesture Handler, so there is nothing native to rebuild if you already use eoria. Wrap the app once, inside `GestureHandlerRootView`:

```tsx
import { BottomSheetModalProvider } from '@gorhom/bottom-sheet'

<GestureHandlerRootView style={{ flex: 1 }}>
  <BottomSheetModalProvider>{/* app */}</BottomSheetModalProvider>
</GestureHandlerRootView>
```

The CLI also adds [Input](/components/input/), because fields inside a sheet switch to the library's text input through it.

## Usage

```tsx
import {
  Sheet,
  SheetClose,
  SheetContent,
  SheetDescription,
  SheetFooter,
  SheetHeader,
  SheetTitle,
  SheetTrigger,
} from '@/components/ui/sheet'

<Sheet>
  <SheetTrigger asChild>
    <Button variant="secondary">Share</Button>
  </SheetTrigger>
  <SheetContent>
    <SheetHeader>
      <SheetTitle>Share trip</SheetTitle>
      <SheetDescription>Anyone with the link can see the route.</SheetDescription>
    </SheetHeader>
    <SheetFooter>
      <SheetClose asChild>
        <Button width="full">Copy link</Button>
      </SheetClose>
    </SheetFooter>
  </SheetContent>
</Sheet>
```

A long text that snaps to half and full height:

```tsx
<Sheet>
  <SheetContent scroll snapPoints={['50%', '92%']}>
    {paragraphs}
  </SheetContent>
</Sheet>
```

### Open it from code

Give `Sheet` a ref when nothing on screen owns the open state. `present()` and `dismiss()` go through `onOpenChange` like a trigger does, so a controlled sheet still decides. `snapToIndex(i)` moves an open sheet to one of its `snapPoints`.

```tsx
import { useRef, useState } from 'react'
import { Sheet, SheetContent, SheetFooter, SheetTitle, type SheetRef } from '@/components/ui/sheet'

export function RenameSheet({ onSave }: { onSave: (name: string) => void }) {
  const sheet = useRef<SheetRef>(null)
  const [name, setName] = useState('')
  return (
    <>
      <Button onPress={() => sheet.current?.present()}>Rename</Button>
      <Sheet ref={sheet}>
        <SheetContent>
          <SheetTitle>Rename list</SheetTitle>
          <Input value={name} onChangeText={setName} accessibilityLabel="List name" />
          <SheetFooter pinned>
            <Button
              width="full"
              onPress={() => {
                onSave(name)
                sheet.current?.dismiss()
              }}
            >
              Save
            </Button>
          </SheetFooter>
        </SheetContent>
      </Sheet>
    </>
  )
}
```

### A searchable list

`SheetList` is the library's virtualised `FlatList`. Put it directly inside `SheetContent` with fixed `snapPoints`. The content then fills the sheet, and the list takes the height left under the header and the search bar. Any eoria field inside the sheet, including [SearchBar](/components/search-bar/), uses the library's text input, so the keyboard lifts the sheet and the rows stay above it.

```tsx
<Sheet ref={sheet} inset="flush" onDismiss={() => setQuery('')}>
  <SheetContent snapPoints={['65%']}>
    <SheetHeader style={{ paddingHorizontal: 24 }}>
      <SheetTitle>Country</SheetTitle>
    </SheetHeader>
    <SearchBar style={{ paddingHorizontal: 24 }} value={query} onChangeText={setQuery} />
    <SheetList
      data={matches}
      keyExtractor={(country) => country.code}
      renderItem={({ item }) => (
        <Item
          onPress={() => {
            onSelect(item)
            sheet.current?.dismiss()
          }}
        >
          <ItemContent>
            <ItemTitle>{item.name}</ItemTitle>
          </ItemContent>
        </Item>
      )}
    />
  </SheetContent>
</Sheet>
```

`keyboardShouldPersistTaps` defaults to `handled`, so the first tap on a row selects it while the keyboard is up. Every other `FlatList` prop passes through.

### After it closes

`onDismiss` on `Sheet` runs once the close animation has finished, whether a drag, the backdrop, Android back, the ref or `open` closed it. Chain the next step there: open another sheet, focus a field, or navigate.

```tsx
<Sheet
  ref={picker}
  onDismiss={() => {
    if (picked) noteField.current?.focus()
  }}
>
```

`onOpenChange(false)` fires when the close starts. `onDismiss` fires when it ends.

## Sizes and snap points

Without `snapPoints` the sheet sizes to its content, grabber included. The library caps that at the height of its container, which is the screen less `topInset`. For a lower cap pass `maxDynamicContentSize` in points, for example `maxDynamicContentSize={height * 0.9}` with `useWindowDimensions`. Content taller than the cap needs `scroll`.

`snapPoints` takes points, or percent strings of the same container: `['60%']`, `[320, '90%']`. List them from smallest to largest. `index` picks the one the sheet opens at and defaults to 0, the first.

With `snapPoints`, dynamic sizing is off unless you pass `enableDynamicSizing`. When it is on, the library inserts the content height into the list and sorts it, so `index` and `snapToIndex` no longer point at the heights you wrote. Leave it off whenever the indices matter.

## Footers

A plain `SheetFooter` sits in the content and scrolls with it. With `pinned` it renders in the library's footer slot instead. It stays on the bottom edge while the content scrolls under it, and rides on top of the keyboard. You can write it anywhere inside `SheetContent`. It renders outside your tree, so context from between `SheetContent` and the footer does not reach it. The sheet's own context and the text input switch do.

`scroll` and `SheetList` pad their content by the pinned footer's height, so the last row clears it.

## The keyboard

Gorhom moves the sheet for the keyboard only when the focused field is its `BottomSheetTextInput`. `SheetContent` and pinned footers provide that input to [Input](/components/input/), [Textarea](/components/textarea/), [InputGroup](/components/input-group/), [SearchBar](/components/search-bar/) and [PasswordInput](/components/password-input/), so you write the usual eoria field. A plain `TextInput` still needs `BottomSheetTextInput` by hand.

Three props decide what happens:

| Prop                        | Values                                | Default here  | What it does                                                                                                      |
| --------------------------- | ------------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------- |
| `keyboardBehavior`          | `interactive`, `extend`, `fillParent` | `interactive` | `interactive` lifts the sheet by the keyboard height. A fixed 60% sheet keeps its full height above the keyboard. |
| `keyboardBlurBehavior`      | `none`, `restore`                     | `restore`     | `restore` puts the sheet back on its snap point when the keyboard closes. `none` leaves it lifted.                |
| `android_keyboardInputMode` | `adjustPan`, `adjustResize`           | `adjustPan`   | `adjustPan` lets the sheet move itself. Use `adjustResize` only if your window really resizes for the keyboard.   |

A lifted sheet never goes above `topInset`, so pass the safe-area top inset: `topInset={insets.top}`. A sheet taller than the room left keeps its top edge there and loses its bottom behind the keyboard, which is why a list sheet works best at 60 to 70%.

Opening a sheet, or closing it any way but a drag, dismisses the keyboard first.

## Dismissal and Android back

Dragging down, tapping the backdrop, Android back, the VoiceOver escape gesture, `SheetClose`, the ref and `open` all close the sheet. Everything except the drag asks through `onOpenChange(false)` first, so a controlled sheet can refuse by keeping `open` true. `dismissable={false}` removes the drag and the backdrop. Back and escape still ask, as they do for [Dialog](/components/dialog/).

Each open sheet listens for Android back. React Native calls the newest listener first and stops at the first that handles the press. The most recently opened sheet closes, the one under it stays, and the press never reaches the navigator. When the keyboard is up, Android uses the first press to hide it before any listener runs, so the sheet closes on the second.

## Stacked sheets

Opening a sheet while another is open follows `stackBehavior`. The default `switch` lowers the first sheet out of sight and brings it back when the second closes. `push` keeps both visible. `replace` closes the first, which fires its `onOpenChange(false)` and `onDismiss`. A lowered sheet is hidden from screen readers.

## Accessibility

When the sheet has finished opening, focus moves to `SheetTitle`. Without a title, pass `accessibilityLabel` to `SheetContent`. The grabber becomes a header with that label and takes focus instead. With neither, focus stays where the screen reader left it.

On iOS the layer around the sheet is marked modal, so VoiceOver stays inside, and the escape gesture closes it. The backdrop is a button named by `closeLabel`. The library's own English labels on the backdrop, grabber and container are turned off, so pass translated `closeLabel` and `accessibilityLabel` strings.

## Notes

Dialog with `placement="bottom"` and Sheet share a frame, a grabber and a title style. Use Dialog for a short question with two buttons. Use Sheet when the content scrolls, snaps to heights, or the user expects to drag it.

The library springs by default. Sheet replaces that with a 220 ms ease-out so it moves like the rest of the kit, and Reanimated skips the animation under the OS reduce motion setting.

The library portals the sheet out of your tree. React context from between the provider and the sheet does not reach its children, so pass values as props or provide the context again inside `SheetContent`. `containerComponent` still passes through and wraps the sheet's own layer.
